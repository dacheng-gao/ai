# 文档审阅与结果验证

审阅目标是发现会误导读者、妨碍任务或改变技术判断的问题。先读请求及材料，分清全面评审、指定方面评审和直接修改；仅评审时不编辑文件。

## 先判断技术与任务，再检查表达

围绕当前文档适用的内容检查，不要求每次交付整张检查表：

- **可信与准确**：关键规则、承诺和结论是否有适用证据？事实、方案、目标和执行结果是否混淆？版本、数字、单位、条件和否定是否正确？
- **任务完整**：目标读者能否据此作出决定或完成操作？是否缺前提、输入、步骤、失败分支或成功判据？完整指满足用途，不指覆盖所有可能主题。
- **结构与查找**：能否快速找到主要结论、操作或规则？标题是否具体，层级是否连贯，背景与细节是否遮挡重点？
- **解释与一致**：陌生术语是否在使用处解释？只展开缩写是否仍不知其含义？同一概念、状态和字段是否使用同一名称？图、表、示例与正文是否相符？
- **可维护与可用**：权威来源是否清楚，链接能否由目标读者访问，命令是否说明前提和占位项，重复契约是否可能漂移？

先处理错误承诺、数据误读和关键遗漏，再处理可读性，最后处理版式。没有发现问题的维度无需列“通过”。不要用任意权重和总分替代具体依据，不把可选风格偏好写成缺陷。

## 输出可执行的审阅意见

对实际问题给出：位置或原文片段 → 问题及读者后果 → 依据或证据缺口 → 建议修法。严重性由它怎样影响实现、操作、验收或承诺来解释；项目已有分级时沿用。

区分已证实错误、相互冲突的材料和无法验证的主张。只凭文档未提及不能断言系统未实现；“读者不知道如何回滚”是文档问题，“系统无法回滚”需要系统证据。

例如：

> 第 2 节“满足 2000 QPS”不能由本次固定 100 并发的结果证明。材料未给出完成请求率，也未覆盖目标负载；建议改为本轮观察摘要，并列出目标负载下的复测需求。保留已观测的时延与错误数据。

没有执行证据时不要输出“全部用例通过”。仅表达润色不更改规则；授权改稿时实际修复可确定的问题，对未决业务决定保持缺口。

## 对照原始材料验证改写

逐项核对影响行为的内容是否保留：主体、条件、数量、范围、时间、单位、否定、例外、状态与限制。示例、图与文字是否新增了材料中不存在的规则？局部改写是否覆盖了用户其他修改？

对重要数字核查口径和计算，针对当前修改检查文件链接、版本一致性及已有文档构建。能覆盖风险的检查通过后停止；不为小改动默认写自动化测试、安装渲染器或运行生产命令。

## 以读者任务检查可理解性

对重要长文或明显改变层次的改写，可让未见原始讨论的读者仅根据文档回答关键问题或走查任务：

- 找到必要前提、输入、操作和成功信号；指出卡住的位置及缺少的信息。
- 解释关键术语和结论适用范围；辨认已确认内容、提案与待验证内容。
- 追溯一个重要结论到证据，说明哪些情况下不能照用。

这可由人工或独立 agent 完成，但模型回答正确仅支持理解检查，不能证明工程事实或客户验收正确。没有进行真实读者、命令或渲染验证时，如实说明限度，不能将自查称为用户验证。
