# 从原始素材到易读的专业文档

本指南用于实质性起草和改写。读者应能找到答案、正确理解条件并完成任务；不要把篇幅、固定章节数或术语数量当成质量指标。

## 最少输入与取材

先利用用户已给出的信息及授权范围内的项目资料。按需要补齐：

- 主题与用途：记录现状、定义目标、提出方案，还是报告结果？读者看完需要作出什么决定或完成什么操作？
- 读者与上下文：角色、已有知识、适用产品版本、运行环境及使用场景。
- 原始素材：现有文档、会议记录、需求或合同、接口契约、代码、日志、测试记录或数据文件。
- 输出约束：目标文件、格式、已有模板、语言、范围，以及必须保留的人工修改。

这些是寻找信息的线索，不是要求用户填写的必填表。只有主题也能先形成明确标为提案的提纲；已知内容可以成稿，缺少依据的业务规则或验收结论保持待确认。若一个缺失事实会实质改变结论，先从资料查明；仍无法查明时询问一个聚焦问题，说明它影响什么，并继续独立部分。

## 让关键陈述有依据

为会影响实现、操作、验收或承诺的陈述建立最小对应关系：陈述 → 来源及定位 → 版本/日期/环境 → 可支持的范围。可用工作笔记，不默认在正文塞入大型证据表。读者需要核查的结论在正文附近保留来源或证据入口。

- 目标规则以有效需求和决定为依据；当前行为以对应版本的实现、配置或运行记录为依据。两者冲突时写出差异，不能用现状覆盖目标。
- 结果以实际执行记录为依据。测试脚本证明有检查方法，不证明检查已通过；截图证明某次观察，不证明所有环境都成立。
- 会议记录先判断是建议、决定还是待办。没有批准信息时不补写批准者、状态或日期。
- 示例帮助理解，不能成为新增契约；模型知识可帮助组织解释，不能替代项目事实。

发现不支持的结论时，缩小结论到证据覆盖的范围，或标明待验证；不以流畅措辞掩盖证据缺口。

## 按结论需要采集证据和数据

先明确待证实的问题，再选择最小的材料或检查。例如“接口返回哪些字段”查同版本契约与序列化配置；“本轮是否达到时延目标”查已约定目标及本轮数据，不先收集所有日志。

1. 判断已有材料是否足够，检查版本、时间窗口、采样范围、环境和适用性。
2. 对授权范围内的现有文件、契约、记录进行只读核查。数据计算保留输入、口径、单位、筛选条件和计算方法，优先复用项目已有分析工具。
3. 需要新增实验时先区分文档编制与实验执行。可以给出采集方案、必要字段和判据；没有执行授权时不启动压测、生产诊断或外部写入。日常文档核查也不默认安装依赖。
4. 说明缺口怎样限制结论。若补充材料不能改变判断，停止采集；不要要求与当前文档无关的资料。

对外产物使用脱敏信息、稳定标识和授权可访问的证据位置，不复制真实凭证、无关个人数据或内部秘密。链接不可访问时说明获取方式或提供允许公开的摘要，不编造可下载地址。

## 先排读者问题，再排章节

起草前在工作笔记中列出少量关键问题，并把材料归到相应问题下；不默认先提交提纲等待批准。标题应让读者知道哪里能找到答案。

- 决策类文档：问题与约束 → 建议或决定及状态 → 理由与证据 → 代价、限制与下一步。重要前提与结论放在一起，不能藏到附录。
- 操作类文档：适用范围与前提 → 操作路径 → 成功信号 → 失败时怎么判断与处理。必要风险放在对应操作前。
- 规格与参考：按行为、状态、接口或字段组织，便于精确查询；不要为了“结论先行”破坏规则索引。
- 结果报告：先说在哪些条件下观察到什么、能作出何种判断，再提供方法、数据与限制。没有目标或证据时说明无法作出的判断。

采用逐层展开：开头是用途和关键答案，中层是完成任务或作出判断的必要内容，细节与推导可放后文或链接。一个小改动可用一段话；复杂文档才需要更多层次。不把背景、操作、参考参数和论证交错到读者无法找到下一步。

## 解释术语，保留技术含义

根据目标读者判断哪些术语需要解释。对该读者可能陌生且影响理解的词，首次实质使用时给出“名称 + 当前场景中的含义 + 必要例子或边界”，之后保持一致。多个频繁使用的陌生术语可加简短词汇表，不强制每篇文档都加。

- 只写“幂等（idempotency）”仍可能让客户不理解；可解释为“同一操作重复提交时，业务结果与执行一次相同”。这不等于请求只传输一次，也不自动表示所有操作都支持该性质。
- 保留字段名、错误码、参数名及必要专业名称，使正文能与界面、契约和日志对应。解释 `retry_limit` 的含义，不把标识符翻译成另一个不存在的字段。
- 优先写谁在什么条件下做什么，结果是什么。删空泛名词与套话，拆长句时保留因果、否定、数量、时间、单位及例外。
- 类比用于入门解释，不能代替精确定义；类比可能误导决策时指出适用边界。对专业读者不必反复解释常识。

示例素材确认：“失败可重试至多 3 次，但重试间隔未知，未确认如何防止重复扣款。”

可写：“请求失败后最多重试 3 次。重试间隔以及避免同一请求重复扣款的处理方式尚未确认，因此现有资料不能证明重试不会造成重复扣款。”

不可写：“系统自动重试，确保交易成功且不会重复扣款。”后者丢失了上限，并把未证实性质写成保证。

## 交付能直接使用的产物

用户要求成稿时交付成稿，而不是只讲写作方法；评审时按评审范围交付问题。保留约定标识、人工修订和事实状态。是否需要目录、图表、摘要或附录，由查找与理解的实际成本决定；不要以完整模板取代具体内容。
