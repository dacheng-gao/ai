# PostgreSQL 的实现选择

在采用 PostgreSQL 做物理设计时读取。下列行为以 PostgreSQL 18 为核对基线；执行时先确认目标主版本、扩展和托管限制，再查该版本文档。数据库能力要减少当前模型的实现复杂度，而不是增加功能数量。

## 类型与数据语义

| 需要表达的事实 | 候选能力与决定依据 |
|---|---|
| 技术身份 | `bigint GENERATED ... AS IDENTITY` 与 `uuid`：按跨节点生成、暴露方式、索引大小和兼容性选择；序列不保证无间隙，ID 顺序不等于业务发生/提交顺序 |
| 精确数量与金额 | `numeric(p,s)` 或有明确单位的整数；确认精度、币种、上界、舍入和换算。浮点适合允许误差的测量；不能用它默认保存精确金额 |
| 时间点或日历 | 时间点用 `timestamptz`，纯日期用 `date`；本地日历时间按语义选 `timestamp`。原始时区/地区规则有业务意义时另存；时间点本身不保留原始地区时区 |
| 状态与分类 | 小且稳定的集合可比较 enum、文本加 CHECK；可管理、有属性的分类更适合引用表。检查演进、排序、客户端兼容及旧值处置 |
| 文本与唯一比较 | `text`/`varchar` 的选择不以猜测性能决定。先定义大小写、排序规则及规范化；表达式索引/适当扩展只在匹配语义时使用 |
| 半结构化内容 | `jsonb` 用于有边界的可变属性或文档；需要原文本语义时评估 `json`/文本。核心关联不能靠文档替代完整性；区分缺失键、JSON null 与 SQL NULL |
| 区间 | range/multirange：先定义端点和时间语义；可用重叠运算及 GiST 排斥约束表达资源冲突 |

`jsonb` 不保留原始格式、对象键序和重复键。GIN 的操作符类要匹配实际运算，热点路径可比较表达式索引或提取成列；整份文档更新仍竞争同一行。

## 约束与竞争

常见语义陷阱：CHECK 不自动拒绝 NULL；默认唯一性允许多个 NULL；复合外键的可空分量可能绕过引用检查。按业务补充非空、`MATCH FULL` 等机制；`NULLS NOT DISTINCT` 需 PostgreSQL 15+。

普通 CHECK 不能保证跨行规则。优先考虑唯一、外键、排斥等可声明机制，再设计事务协议；用户函数包装查询不是漏洞修复。主键、唯一与排斥约束会建立相应索引，引用端外键索引不会自动建立。

- **条件唯一**：部分唯一索引可限制活跃记录；先确认“活跃”的定义。普通外键不能把部分唯一索引当引用目标。
- **不重叠**：range + `EXCLUDE USING gist`；等值作用域可需要 `btree_gist`，核对可安装性。检查空/无界范围、取消后的规则、端点及更新竞争。
- **延迟检查**：仅在事务中确需临时违反、提交时恢复时考虑可延迟的约束；核对具体约束类型、引用和 upsert 限制。
- **跨租户关联**：共同作用域进入候选键和复合外键。RLS 属于访问策略，不能替代关系一致性，也不自动解决拥有者/特权角色绕过问题。
- **触发器**：仅在明确的写入口控制或原子维护需要时选择；隐藏的写入、递归、锁顺序、批量和错误语义均有成本。查询其他行的触发器也需要正确隔离或锁协议。

读取与修改同一行时，可用条件更新/版本比较并检查 `RETURNING`；需要集合级裁决时比较共同 guard 行锁与 Serializable。Read Committed 的语句快照和 Repeatable Read 的稳定快照，都不自动保证所有业务不变量。Serializable 仍可能失败，重试整个事务；隔离级别不是越高越好。

`SELECT ... FOR UPDATE` 不锁住不存在的行。`SKIP LOCKED` 适合允许跳过被占用任务的队列领取，不能给需要完整结果的业务查询使用。事务内远程调用会延长持锁时间，本地提交不能使远程副作用原子化。

## 索引与维护成本

| 能力 | 适用依据与限制 |
|---|---|
| B-tree | 等值、范围、排序及唯一性；列序跟实际谓词/排序匹配。混合排序、NULL 顺序和比较表达式会影响利用 |
| 部分索引 | 常访问的稳定子集；查询须在规划时可证明满足谓词。核对预处理语句的 generic/custom plan，不能假设参数值总能证明条件 |
| 表达式索引 | 查询同一表达式及比较规则；函数需满足索引要求。对原列包函数不等于原列索引可直接定位 |
| `INCLUDE` | 覆盖返回列；不参与键查找或唯一性。仅有覆盖不保证无回表，频繁更新会影响可见性图并增加维护 |
| GIN | JSON、数组及全文等包含/检索运算；匹配操作符类，评估写入与维护成本，不替代 B-tree 排序 |
| GiST/SP-GiST | range、空间或特定搜索结构；以数据类型、运算和实际计划判断，不视为通用加速器 |
| BRIN | 大量数据且物理位置与筛选值相关；小索引换取较粗候选与复查。数据“有时间字段”不足以证明适用 |

PostgreSQL 18 的 B-tree skip scan 让某些非前导列条件也可能有效利用复合索引；不要写“缺少最左列绝不走索引”。但这不等于列序无关，仍需按分布和计划检验。

频繁更新会生成新行版本。普通索引涉及的键、INCLUDE、表达式或谓词列变化会影响 HOT 机会；HOT 还需要页内空间，BRIN 等汇总索引有不同处理。不要默认给频繁变化的计数器、时间戳建索引；按查询收益决定，再评估 WAL、死元组、vacuum 和膨胀。

分区用于有依据的裁剪、保留期和维护需求，不是“行多就分”。核对分区键对唯一键/引用的影响、跨分区查询、分区数量和自动维护；PostgreSQL 18 的分区父表唯一/主键约束须包含所有分区键。拆进各分区的冲突检查不能自动保证跨分区规则。

## 演进与核实入口

常量默认值在某些现代版本可避免整表回写，但 DDL 仍可能取锁；“加可空列”也不能直接称为在线无风险。拆成扩展、兼容读写、分批回填、核对、切换和收缩，仅保留当前变更必要的阶段。

`CREATE INDEX CONCURRENTLY` 不能在事务块内执行；失败可能留下 INVALID 索引，减少写阻塞不等于没有锁或等待。检查迁移工具的事务策略和具体版本限制。添加/验证约束的锁、扫描与 `NOT VALID` 支持按类型核实。

优先查看目标版本下的 `ddl-constraints`、`datatype-*`、`rangetypes`、`indexes-*`、`transaction-iso`、`explicit-locking`、`storage-hot`、`ddl-partitioning`、`sql-createindex`、`sql-altertable`。链接与本次核实范围见 [sources.md](sources.md)。
