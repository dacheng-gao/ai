# 负载、读写权衡与证据

在索引、事务竞争、冗余或性能承诺需要判断时读取。不要为了填表收集与当前决定无关的指标。

## 最小访问记录

为受影响的重要路径写实际 SQL 或足够精确的访问形状：

| 项目 | 需要知道什么 |
|---|---|
| 业务与正确性 | 查什么事实；需要哪个时间点/快照；允许多旧 |
| 访问形状 | 等值/范围条件、连接、排序、分页、聚合与返回列 |
| 数据与分布 | 当前/预计行数、值分布、关联和倾斜、返回数量、宽度 |
| 工作强度 | 调用频率、并发、批量、长短事务与真正热点 |
| 写入影响 | 哪些列常变、索引/投影受影响、锁的范围与保持时间 |
| 证据 | 来源、现有指标和目标；缺失项明确未知 |

查询例：`WHERE tenant_id = ? AND status = 'booked' AND starts_at >= ? ORDER BY starts_at, id LIMIT ?`。复合索引候选 `(tenant_id, starts_at, id) WHERE status = 'booked'` 对应一个具体路径，而不是为所有列分别建索引；目标数据库能否采用还需要计划验证。

## 索引取舍

1. 列出现于 WHERE/JOIN 不直接证明要单独索引。先检查约束索引、复合索引、扫描比例、返回数量和表大小；顺序扫描可能正确。
2. 综合等值前缀、范围、排序、limit、连接方向、表达式和覆盖需求选列序。范围右侧列可能仍可过滤；不能把“等值→范围→排序”当通用机械公式。
3. 查询筛选、排序和分页必须使用一致的比较语义。多个单列索引的 bitmap 组合不保证排序；复合索引能用也不保证划算。
4. 游标分页用明确且稳定的全序键，并处理同值、NULL 和方向；修改排序键或并发新增/删除仍可能改变翻页结果。若要整个浏览过程固定快照，明确实现与成本。
5. 唯一索引同时保证正确性与支持访问，不因“查询没用到”就删除。其他索引去留需考虑统计观察期、低频关键任务及父记录删除/更新检查。
6. 每个候选注明支持的路径和写入代价；部分/覆盖/表达式索引、宽键及重复前缀需特别说明保留理由。

## 写入和一致性

先观察热点是行、键范围、序列、集合 guard、索引维护还是持锁时间。加连接/线程或重试可能只增加排队。批量写入减少往返，但事务太大会增加 WAL、持锁、回滚和复制延迟；分批要保持业务原子性或有可恢复协议。

只有读取收益可解释时，才预计算汇总或维护读模型。记录：

- 原始事实及完整推导口径；
- 同事务维护或明确延迟，不把严格规则改成最终一致；
- 重复、乱序、遗漏与部分失败的处理；
- 重建、核对、切换与读取新鲜度；
- 写放大、热点和维护责任。

跨表总量限制不能靠读取 SUM 后插入维护。可共同锁住稳定 guard 行并在新语句中重新读取，或用可串行化协议/有证明的原子余额维护；确认新增、取消、移动、批量和其他入口遵守同一协议。

读副本、缓存和物化视图各有新鲜度及故障语义。外部消息/调用需要可靠交付时，在业务提交内保存发送意图，再按已有机制发送和去重；不为了做数据库设计另建消息架构。

## 判定成败的检查

验证先定义能推翻错误设计的预期，再执行；不写只匹配 DDL 文本的“正确性测试”。

| 风险 | 有辨别力的证据 |
|---|---|
| 表粒度或关系错误 | 一段完整合法业务能准确写入和还原；多个明细/角色不会被错误键拒绝或产生伪组合 |
| 完整性缺口 | 直接 SQL 尝试 NULL、重复、错误范围、孤儿、非法删除，核对具体约束与提交结果 |
| 历史被改写 | 修改主数据后，旧凭证/快照仍按约定读取；纠错和迟到记录有明确口径 |
| 并发超限/重复 | 两个独立会话在相同前提下交错竞争；读取已提交结果，检查至多一个成功、允许的拒绝及恢复 |
| 查询或索引错误 | 真实参数、偏斜、数据量与统计信息下比较计划和结果；不能用强制禁用顺序扫描证明效果 |
| 写路径退化 | 有/无候选索引的对照：更新延迟、锁等待、WAL、存储、vacuum/膨胀等与实际风险相关的指标 |
| 演进故障 | 旧数据、同时运行的新旧客户端、回填中断与重试、锁等待和切换时的可恢复性 |

PostgreSQL 可在隔离环境使用 `EXPLAIN (ANALYZE, BUFFERS)`；它会实际执行语句。写语句会产生修改、触发器行为和锁，ROLLBACK 不保证序列或外部副作用撤销；未经相应授权不在真实数据上执行。

关注估计与实际行数、循环、过滤量、缓冲区、排序/哈希落盘、回表及锁等待；相关列估计有偏差时先查统计信息，按需评估扩展统计。执行计划的 cost 不是毫秒；命中索引不是性能验收。

对照保持数据、参数、数据库/客户端配置、并发与统计状态可比较，说明缓存冷热、维护状态和测量方法；只有波动会改变决定时才增加采样。微型合成数据可以验证结构，不能代表生产性能。数据缺失时交付可运行的验证方案，不伪造测量或要求用户先提供完整容量规划。

## 收敛与报告

报告实际版本、环境与数据条件、检查命令/关键结果、已证实结论、失败及未验证部分。有依据的性能数字只对测量条件负责。一个复杂业务的推演、DDL 语法通过或一次执行计划，都不能独自证明成熟的设计。
