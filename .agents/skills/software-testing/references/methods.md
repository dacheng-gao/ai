# 选择能拒绝错误实现的测试

## 实例化需求与例子映射

围绕一个行为，把故事/目标、规则、具体例子和未决问题分开。让业务、研发、测试已有材料互相对照；agent 可提出遗漏，但不能假扮三方已达成共识。

每条有争议的规则选择能区分不同解释的例子。预期不清楚时保留问题，不急于写 Gherkin。确认后的关键例子连接到自动化检查，作为可维护的行为说明；规则改变时一起更新。不要为了方法完整给显然的规则批量补例子。

*Specification by Example* 关注从协作澄清到验证与持续维护；例子映射是 Matt Wynne 的相关工作方法，不能误称为 Adzic 原书的同名流程。

## 从规则推导检查

- **等价类与边界**：按产生不同业务决策的输入分组，选择边界内、边界上和边界外；边界的单位、精度、包含关系必须来自规则。
- **决策表**：多个条件共同影响结果时，列有效组合和优先关系，寻找重叠、空白与矛盾。不要穷举不可能组合或自行填上未知政策。
- **状态与序列**：检查合法/非法转换、重复动作及失败后的事实。顺序会影响结果时，单次接口测试不足。
- **不变量/性质**：适合大量输入的规则可用性质测试；性质必须独立来自契约，例如满足适用条件的编码解码往返，而不是照抄实现表达式。
- **竞争**：明确交错操作及提交后事实；共享内存测试不能证明目标数据库的隔离与约束。

反例（假设规则）：退款不得超过剩余可退金额。只测试退款 10 元成功，无法发现总额未扣减的错误；根据已确认规则验证边界、重复意图和并发竞争中实际相关的情况。是否累计、是否允许部分退款等仍须业务依据。

## 选择测试边界

纯规则在单元级获得快速反馈；SQL、真实序列化、事务和适配器契约在集成级验证；跨服务消费关系必要时做契约检查；少量关键用户流程做端到端验证。

以最便宜且仍能暴露真实失败机制的层次为起点。mock 能模拟超时，但不能证明实际重试协议不会重复扣款；浏览器 UI 全绿不能单独证明后台数据完整性。覆盖率用来寻找未观察路径，不能作为业务正确性的替代指标。

单测与集成测试共享预期构造逻辑时，检查是否可能复制了同一个错误。测试应断言外部可观察契约或必要不变量，不绑定无业务意义的内部调用次数。

## 好测试的四要素与 mock 边界

Vladimir Khorikov《Unit Testing: Principles, Practices, and Patterns》把测试价值拆成四项：防回归、耐重构、快速反馈、易维护。前三项相互制约，耐重构基本是“有或没有”的性质，应尽量保住；因此在防回归与反馈速度之间按风险取舍。

- **测可观察行为**：断言调用方能观察到的输出、状态变化或对外交互，不断言私有方法、内部调用顺序或中间结构。与实现细节耦合的测试会在合法重构时误报，久而久之被忽略。
- **托管与非托管依赖**：只有本应用访问的进程外依赖（通常是自己的数据库）是托管依赖，其交互是实现细节，优先用真实实例在集成测试中验证；外部系统可观察的依赖（第三方 API、消息总线、SMTP）是非托管依赖，其交互属于契约，用 mock 或契约测试验证。
- **单元的含义**：单元是一个行为单元，不必是一个类；在进程内协作的对象通常不必相互 mock。
- **测试强度的证据**：覆盖率只说明代码被执行过，不说明断言有效。对关键规则，可手工或用变异测试工具把条件取反、边界加减一，确认测试会失败。

## 探索式测试

用短任务章程约束探索：探索哪个区域、使用什么变化、为了发现哪类风险、何时结束。执行过程中根据新发现调整下一次实验。

从交互、序列、数据、时机、配置或环境中选择相关变化。例如在慢请求期间离开页面，再返回观察最终状态；只有产品支持这类操作且测试环境允许时执行。记录版本、关键步骤、观察、判定依据和未解决问题，保留可复现证据。

探索不是无目的点击，也不要求预先写全所有用例。没有明确判定依据的异常先称为疑点，回到规则或契约核查。

## 质量属性与验收

性能检查先确定负载、代表性数据、预热/测量条件、延迟口径、吞吐与错误，检查结论是否超出环境；安全检查对准资产、权限与信任边界；可用性检查使用真实目标任务与参与者。必要专门工具按项目和授权选择，不能把一般自动化测试称为全面认证。

业务验收关联需求来源、版本、角色、任务、结果及实际确认记录。无确认者或真实记录时只报告技术验证/验收准备，不制造签收。

## 结果与退出

针对每个重要风险区分：已经观察、检查通过、检查失败、未执行、不适用。失败保留最短复现和影响；脆弱用例查根因而非一律重跑。已有检查充分时停止扩充。

Adzic 的约 50 个项目案例、Hendrickson 的方法书与 Khorikov 的单元测试原则提供实践依据；它们不证明某固定测试比例适合所有系统。项目实际缺陷与反馈应决定调整。
